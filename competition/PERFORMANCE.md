# Производительность: честный протокол

**Состояние:** опубликованных замеров одного контейнера 2–4 vCPU / 2–4 ГБ RAM с сотнями RPS и p95 < 200–300 мс **нет**. Ниже — воспроизводимый план теста, а не цифры для жюри. Не заполнять поле RPS вымышленным результатом.

| Поле PDF | Значение сейчас |
| --- | --- |
| Количество контейнеров, лимит CPU и памяти тестового запуска | не зафиксированы |
| Конкурентность, длительность, прогрев, набор запросов | не зафиксированы |
| RPS, p50/p95/p99, ошибки HTTP | не измерены |
| CPU %, peak/stable RAM, swap | не измерены |
| Горизонтальное масштабирование | архитектурно возможно для read-only CSV, фактически не проверено |

Для отчёта: (1) положить конкурсный CSV и auth локально; (2) запустить сервис с лимитами Compose/контейнера; (3) прогреть день и месяц по нескольким маршрутам; (4) нагрузить `GET /api/forecast` и `GET /api/export` отдельно через `wrk`/`k6` с активной cookie и реалистичным соотношением запросов, повторить 3 раза; (5) зафиксировать точную команду, железо, RPS, p50/p95/p99, 4xx/5xx, CPU/RAM/swap, хеш образа и CSV. `/health` не заменяет тест прогнозного API.

PDF требует **обязательно указать данные о производительности в README**. Пока тест не выполнен, этой части критерия доказать нельзя. После замера внести таблицу измерений сюда и короткое резюме в `README.md` той же ревизией.
