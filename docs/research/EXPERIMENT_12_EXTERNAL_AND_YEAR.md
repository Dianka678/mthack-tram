# Опыт 12: погода, трафик, геометрия и годовой горизонт

Дата аудита: 26.09.2026 (МСК). Контракт сверён с
[`docs/DS_REQUIREMENTS.md`](https://github.com/Dianka678/mthack-tram/blob/fullstack/scenario-console/docs/DS_REQUIREMENTS.md)
в ветке fullstack. В текущих метках есть только маршрут, дата, час и число
успешных валидаций. Датированных архивов погодных **прогнозов**, маршрутного
трафика и корректной исторической геометрии в предоставленных файлах нет.
Поэтому для этих трёх групп нет честного WAPE «с признаком» на срезах
30.04, 30.06 и 31.08. Статус эффекта — **не измерен**.

## Пригодность факторов на дату отсечения

| Группа | Проверенный кандидат и источник | Исторический backtest на двух месяцах | Год вперёд |
| --- | --- | --- | --- |
| Погода | Температура, осадки, снег и экстремумы по району/часу. [ERA5](https://open-meteo.com/en/docs/historical-weather-api) даёт наблюдённую позже погоду с задержкой около пяти суток. [Архив прогнозов](https://open-meteo.com/en/docs/historical-forecast-api) и [выпуски моделей](https://open-meteo.com/en/docs/single-runs-api) потенциально позволяют соблюсти `as_of`. | Нужны архивные выпуски, выпущенные **до каждого cutoff**, для всего целевого интервала. Доступный через интерфейс архив фактической погоды не подставлять в операционный backtest. Подключение погодного API в этой среде заблокировано; данных за 2025 здесь не извлекли. | [Сезонная система](https://open-meteo.com/en/docs/seasonal-forecast-api) описывает ансамбль на срок до 7 месяцев с невысоким пространственным разрешением; почасовой достоверный дождь на год она не предоставляет. Для конца года — только климатическая неопределённость и ручные сценарии. |
| Трафик | Почасовая загруженность **затронутых улиц** и дата публикации, плюс принадлежность маршрута выделенному полотну. [ЦОДД](https://gucodd.mos.ru/) показывает текущий индекс, [городской набор](https://data.mos.ru/opendata/62525/description) описывает среднемесячную загруженность. | Текущий индекс — информация будущего относительно исторической отсечки, а среднемесячный городской индекс без времени публикации и трассы не заменяет почасовой трафик. Подходящего исторического ряда нет; WAPE не вычислен. | Фактические будущие пробки недоступны. Плановые перекрытия включать только при подтверждённых маршруте, месте, сроках и `published_at`. |
| Геометрия | Длина/ориентация трассы, число пересадок, расположение относительно магистралей; [городской GTFS](https://data.mos.ru/opendata/60661/description) с архивными версиями и датой публикации. | В предоставленном справочнике лист `Порядок_с_координатами`: 622 строки данных, `actual_date` с 20.10.2025 по 09.02.2026. Для отсечек апреля, июня, августа **0 подходящих строк**; есть не все девять маршрутов с метками. Ретроспективный маппинг невозможен. | Статичная геометрия — константа маршрута; текущий профиль уже отдельно оценивает маршрут. Нужны датированные изменения и взаимодействие с погодой/работами, а также метод для маршрута 5 без обучающих меток. |

Эти поля сформируют проверяемую матрицу `route × date × hour` лишь при
получении версий, доказуемо доступных до каждой отсечки. Если будет
ретроспективная фактическая погода, её эффект можно считать **отдельным
competition/diagnostic опытом**, не операционным годовым прогнозом.

## Проверка достижимого исторического горизонта

Парные сравнения на одинаковых временных срезах: медианный или средний
профиль `route × weekday × hour` с 20% сглаживания к `route × hour`, полная
24-часовая сетка девяти известных маршрутов. Будущие метки используются
только для оценки; внутренние дневные отсутствия считаются нулём **для
метрики**, без утверждения о причине пропуска.

| Обучение до | Проверка до 31.10 | Горизонт | Средний WAPE-score | Медианный WAPE-score |
| --- | --- | ---: | ---: | ---: |
| 28.02.2025 | 01.03–31.10 | 8 месяцев | 0,817645 | **0,823593** |
| 30.04.2025 | 01.05–31.10 | 6 месяцев | **0,818177** | 0,801217 |
| 30.06.2025 | 01.07–31.10 | 4 месяца | **0,827289** | 0,816439 |

[Полный JSON с ошибкой по маршрутам и пиковым часам](results/year_horizon.json),
[скрипт](experiment_year_horizon.py). Эти срезы перекрываются по целевым
месяцам и **не являются** тремя независимыми повторениями. Меток на целый
год вперёд нет, поэтому качество годового горизонта не измерено.

DS‑1: новый запуск `python -m ml.forecast.year` строит 365 или 366 дней
почасового профиля по меткам только до указанной отсечки. Он сохраняет
`yearly_forecast.csv`, `yearly_forecast_api.csv` с московскими ISO-часами,
версией и флагом качества, а также `yearly_report.json` с SHA исходных и
выходных файлов. Пример на метках по 31.10.2025 сформировал **87 600** строк
для десяти маршрутов с 01.11.2025 по 31.10.2026. Маршрут 5 без истории —
нулевой технический заполнитель с флагом `unsupported_cold_start`, а не
проверенный прогноз. Остальные часы отмечены `long_horizon_unverified`.
Это отдельный исследовательский экспорт: ранее поданный конкурсный CSV
не менялся. Последние доступные метки октябрьские, их фактические времена
поступления не даны и это ограничение указано в отчёте.

```bash
python docs/research/experiment_year_horizon.py \
  --train /path/to/labels_day_train.csv \
  --test /path/to/labels_day_test.csv \
  --out /path/to/year_horizon.json
PYTHONPATH=. python -m ml.forecast.year \
  --labels /path/to/labels_day_train.csv /path/to/labels_day_test.csv \
  --cutoff 2025-10-31 --days 365 --out /path/to/year_forecast
```
