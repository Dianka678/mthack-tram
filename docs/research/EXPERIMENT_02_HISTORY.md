# Эксперимент 02: сколько истории брать для прогноза

26.09.2026 (МСК). Гипотеза из блока тренда [матрицы факторов](FACTOR_MATRIX.md): недавние недели точнее описывают будущие месяцы, чем вся история. Зафиксированы те же метки, сетка, `route × weekday × hour`, 20% сглаживания, правило отсутствующих ключей и два периода оценки, что и в [первом backtest](RESULTS_2026-09-26.md). Изменяется **только длина истории**: вся доступная / последние 28 / 56 / 84 / 112 / 168 дней. Для каждой длины проверяются среднее и медиана. Ни один факт из прогнозируемого периода не подаётся в модель.

## Воспроизведение

```bash
python docs/research/experiment_history_window.py --train /path/to/labels_day_train.csv --test /path/to/labels_day_test.csv --out /path/to/history_window.json
```

Скрипт: [experiment_history_window.py](experiment_history_window.py). [JSON с WAPE-score по всем вариантам и маршрутам](results/history_window.json). Отчёт содержит только агрегаты.

## Результат (WAPE-score, больше лучше)

| История | Июль–август: среднее | Июль–август: медиана | Сентябрь–октябрь: среднее | Сентябрь–октябрь: медиана |
| --- | ---: | ---: | ---: | ---: |
| Вся история | 0,783548 | 0,739241 | 0,847404 | **0,867992** |
| 28 дней | **0,824458** | 0,812474 | 0,777027 | 0,785391 |
| 56 дней | 0,806575 | 0,783907 | 0,756203 | 0,755441 |
| 84 дня | 0,790568 | 0,759767 | 0,775728 | 0,788601 |
| 112 дней | 0,774722 | 0,741841 | 0,809431 | 0,816997 |
| 168 дней | 0,764513 | 0,729141 | 0,835075 | 0,845576 |

На первом срезе 28-дневное среднее лучше среднего за всю историю на **0,040910** балла. На втором оно хуже на **0,070377**; по сравнению с лучшей медианой за всю историю проигрыш **0,090965**. Модель после августа, пользуясь коротким окном летнего спроса, сильно недооценивает сентябрь–октябрь: сумма `prediction − actual` у среднего за 28 дней составляет **−2 026 073** против **−861 398** у среднего за всю историю. Выбор 28 дней по одному срезу был бы переобучением на периоде валидации.

**Решение:** гипотеза «чем меньше окно, тем лучше» отвергнута для двухмесячного горизонта. Использовать короткую историю только как дополнительный признак рядом с долгосрочной сезонностью, если парное сравнение улучшит оба среза. Итоговую модель и прогноз ноября–декабря этот опыт не определяет: маршрут 5 в метках отсутствует, исторические изменения сети не включены.

## Очередь опытов из матрицы

1. **Работа маршрутной сети:** составить журнал `route, valid_from, valid_to, published_at, status, source_url`; результат проверки маршрутов 7 и 50 в [кейсе](CASE_STUDIES_2025.md). Для честного backtest использовать только сообщения, известные до его cutoff. Поздние новости проверять в отдельно названном сценарии.
2. **Календарь:** следующий парный опыт; исходный baseline уже знает `weekday`, поэтому тестировать именно новые признаки выходных по переносу, каникул и праздников, а не повторять день недели. Если в июле–октябре нет соответствующих событий, добавить отдельный более ранний срез для проверки, не объявляя нулевое покрытие успехом.
3. **Погода:** после календаря и версии расписания. Сначала установить исторические почасовые факты и доступные на дату отсечения прогнозы, потом сравнить `base` и `base + weather` на одинаковых срезах. Режимы `competition` и `as_of` не смешивать.
4. **Остальные источники** (дорожная обстановка, события, геометрия): только при наличии датированного ряда, точной связи с маршрутом и возможности повторить парный backtest. Непроверенные источники остаются в статусе гипотез.

План экспериментов выполняется последовательно: одна группа признаков → покрытие и дата публикации → два одинаковых backtest → решение по WAPE и ошибкам маршрутов. На текущий момент численный эффект **внешних** источников ещё не измерен.
