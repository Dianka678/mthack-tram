# Исследование данных и факторов трамвайного прогноза

Здесь находятся воспроизводимый аудит исходных валидаций, контрольная модель и
протокол исследования внешних источников. Исходный `train.csv` (около 7,59 ГБ),
`test.csv`, хеши карт и отчёты с детализацией транзакций **не коммитить**.
Результаты `summary.json` и `backtest.json` содержат только агрегаты.

## Что уже установлено по файлам организаторов

- `train.csv`: январь–август 2025; `test.csv`: сентябрь–октябрь 2025.
  Разделитель `;`, UTF-8. Цель — число записей с `validation_result == 1`
  по `ngpt_route` и часу `tran_date_time`. `input_date_time` может быть битым.
- `labels/labels_day_train.csv` (46 234 строк) и
  `labels/labels_day_test.csv` (11 317 строк) содержат готовые агрегаты с
  колонками `route;date;hour;boardings`. В них девять маршрутов; строк с
  `boardings == 0` нет. Отсутствующий ключ ещё не доказывает нулевой спрос.
- `test_submission.csv` — 14 640 строк, 10 маршрутов × 61 день × 24 часа;
  `route;date;hour;prediction`. Маршрут 5 есть только в шаблоне.
- В предоставленном справочнике имеются записи с `actual_date` в конце 2025
  и в 2026 году. Не использовать его как неизменную историю всей сети с января.
  `place_id` в сыром CSV — площадка/депо, не ID остановки. Остановочная
  детализация из имеющихся меток не идентифицируется.

## Быстрый старт: метки можно анализировать без 7,59 ГБ

Python 3.10+; внешних библиотек для двух скриптов не требуется.

В PowerShell из корня проекта (замените пути на свои):

```powershell
python docs/research/profile_data.py --labels "D:\dataset\labels\labels_day_train.csv" --labels "D:\dataset\labels\labels_day_test.csv" --submission "D:\dataset\test_submission.csv" --out "D:\mthack_reports\labels"
python docs/research/backtest_baseline.py --train "D:\dataset\labels\labels_day_train.csv" --test "D:\dataset\labels\labels_day_test.csv" --out "D:\mthack_reports\backtest"
```

Первый скрипт проверяет схему и полную сетку шаблона, второй сравнивает
средний и медианный профиль `route × weekday × hour` на двух последовательных
срезах. Все 24 часа на каждом маршруте включены в знаменатель WAPE;
неуказанный в метках час принимается равным нулю **только для конкурсного
счёта**. Диагностика реальных нулей и сбоев требует сырого CSV.

## Потоковый аудит полного train.csv

```powershell
python -u docs/research/profile_data.py --input "D:\dataset\train.csv" --labels "D:\dataset\labels\labels_day_train.csv" --out "D:\mthack_reports\train" 2>&1 | Tee-Object "D:\mthack_reports\train_progress.txt"
```

Файл читается строка за строкой. В память попадают только счётчики и суммы по
маршруту/дате/часу; пассажирские хеши, номера устройств и строки транзакций
не сохраняются. Прогресс печатается каждые 2 млн строк. Для быстрой проверки
сначала добавьте `--max-rows 100000`; полный проход выполняйте **без** этого
параметра. Не запускайте полный train одновременно с другими тяжёлыми задачами.
Если `test.csv` остался в ZIP, допустим путь вида
`--input "D:\dataset\test.zip::test.csv"`.

Отправьте мне `summary.json` из `train` и `backtest.json`. Файлы
`hourly_route.csv`/`daily_route.csv` нужны для внутреннего анализа; они содержат
агрегаты организаторов и не требуются для первичного обсуждения. Не отправляйте
сырые транзакции, `crd_hashcode`, ключи доступа и `train_progress.txt`, если
в нём окажется локальный путь или другая частная информация.

Если суммы сырых успешных валидаций и меток расходятся, проверьте дату по
`tran_date_time`, хвост следующего месяца, код успеха, состав маршрутов и
дубликаты. Скрипт сравнивает объединение ключей без автоматической правки.
На присланном `test.zip` полный проход прочитал 13 391 571 строк за 69 секунд
в этой среде. Успешных событий 12 754 520 против 12 754 481 в
`labels_day_test.csv`: различаются 27 часовых ключей, только на границах
01.09 и 01.11. Начало сентября частично лежит в хвосте train, а начало
ноября — в хвосте test. Суммировать файлы и фильтровать **по времени события**;
не объявлять эти 39 записей ошибкой меток или новым фактором спроса.

## Уже выполненный контроль на присланных метках

| Срез | Средний профиль | Медианный профиль |
| --- | ---: | ---: |
| Обучение до 30.06 → июль–август | 0,7835 | 0,7392 |
| Обучение до 31.08 → сентябрь–октябрь | 0,8474 | 0,8680 |

Это локальный WAPE-score девяти маршрутов по полным часовым сеткам, без
маршрута 5 и без неизвестного эталона ноября–декабря. Срезы имеют разные
обучающие периоды; по ним нельзя утверждать, что медиана всегда лучше.

[матрице](FACTOR_MATRIX.md).
