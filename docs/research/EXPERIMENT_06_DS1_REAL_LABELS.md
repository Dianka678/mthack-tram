# Опыт 06: кандидаты DS‑1 на фактических почасовых метках

Дата: 26.09.2026 (МСК). Код [чернового PR DS‑1 № 3](https://github.com/Dianka678/mthack-tram/pull/3),
исходный commit `613da6c8e5134107af4094db45f4433a0ced76e1`.
Это независимый запуск кода DS‑1 с доступными DS‑2 реальными агрегированными
метками; файлы сырого набора данных и прогнозный CSV в GitHub не добавлены.

## Вход и протокол

`labels_day_train.csv` (январь–август), `labels_day_test.csv`
(сентябрь–октябрь), исходный `test_submission.csv` организаторов. Контрольные
SHA256 файлов есть в [`results/ds1_real_candidates.json`](results/ds1_real_candidates.json)
и в локальном полном отчёте запуска DS‑1. По всем девяти маршрутам с метками
сравнили пять профилей и два варианта `HistGradientBoostingRegressor`. Каждый
прогнозирует **весь** проверочный период без подстановки фактов из него в лаги.
Отсутствующие метки трактуются как ноль только для метрики; альтернативные
`*_observed` проверяют чувствительность к пропускам при обучении.

| Период и отсечка | mean_zero | median_zero | mean_observed | median_observed | mean_56d | hgb_direct | hgb_recursive |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Май–июнь, 30.04 | **0,816977** | 0,798214 | 0,803264 | 0,784916 | 0,795240 | 0,803120 | 0,778721 |
| Июль–август, 30.06 | 0,783548 | 0,739241 | 0,777432 | 0,733355 | 0,806575 | **0,827134** | 0,816737 |
| Сентябрь–октябрь, 31.08 | 0,847404 | **0,867992** | — | — | — | 0,823864 | — |

Значения — WAPE-score (`max(0, 1 − Σ|ошибка| / Σфакт)`), выше лучше. По
протоколу DS‑1 кандидата выбирают по **сумме абсолютных ошибок** мая–августа,
а сентябрь–октябрь служит воротами против контрольных профилей. На развитии
выбран `hgb_direct`: сумма ошибок **4 127 846** против **4 434 848** у
`mean_zero`. На сентябре–октябре он хуже обоих контролей: **2 246 520**
ошибок против **1 683 697** у `median_zero`. Поэтому правило DS‑1 выбирает
**`median_zero`**. Проверочный период участвует в выборе модели и не является
нетронутым независимым тестом итогового качества.

Полная команда DS‑1 на этих же метках завершилась без ошибки, повторила все
указанные оценки и создала локальный `submission.csv`: **14 640 строк**,
10 маршрутов, 1 464 строки маршрута 5, который отсутствует в исторических
метках и пока получает нули. Строгая валидация структуры и порядка шаблона
прошла. Локальная версия модели `ds1-median_zero-65485092e235`, SHA256
прогнозного CSV `371d05c44e20b63db110f5a5e27b8da8fafb785fdbc66374307b0ab7304a75ac`.
Результат платформы неизвестен, внешние факторы в этом CSV не включены.

## Решение для улучшения модели

Прямой бустинг нельзя утверждать победителем по одному июлю–августу: на
последнем контрольном срезе он уступает регулярному профилю. Сохранить
`median_zero` как текущий кандидат для выгрузки DS‑1, затем измерить на
одинаковых срезах добавление подтверждённых календарных и сетевых признаков.
Календарное правило опыта 03 улучшило май–июнь, но его влияние на неизвестные
ноябрь–декабрь ещё не измерено. Для № 50 проверить расписание и исключения
13 сентября; по сырым записям эта дата не равна нулю.

Воспроизведение из checkout PR DS‑1 с реальными файлами в локальных путях:

```bash
python docs/research/experiment_ds1_candidates.py \
  --ds1-root /path/to/ds1-checkout \
  --train /path/to/labels_day_train.csv \
  --test /path/to/labels_day_test.csv \
  --out /path/to/ds1_real_candidates.json
```

Для полного запуска с экспортом см. `ml/forecast/README.md` в PR DS‑1.
Локальный CSV и модель не коммитить. Сравнение по маршрутам, месяцам, пикам
и маске отсутствующих меток находится в JSON результата.
