# Прогноз загрузки трамвайных маршрутов Москвы

План и стартовая структура команды из двух Data Scientist и одного fullstack-разработчика. Приоритет при расхождении материалов: `требованич.docx` → ответы экспертов → PDF кейса. Полное руководство: [docs/PLAN.md](docs/PLAN.md). Текущее состояние и контракты: [PROJECT_STATE.md](PROJECT_STATE.md).

## Быстрый старт команды

1. Рабочий репозиторий команды — [`Dianka678/mthack-tram`](https://github.com/Dianka678/mthack-tram). Примите приглашения в GitHub и подключите собственные ИИ-инструменты к этому репозиторию с разрешения своих аккаунтов.
2. Все читают `docs/PLAN.md`, `AGENTS.md` и `PROJECT_STATE.md`; в GitHub Issues создают три задачи `DS1`, `DS2`, `FULLSTACK` с критериями готовности из плана.
3. DS‑1 получает `dataset.zip` по ссылке организаторов, сверяет `sample_submission` и записывает точные имена столбцов и правила агрегации в `PROJECT_STATE.md`. Сам архив, данные о транзакциях, логины и пароли в GitHub не загружать.
4. Fullstack фиксирует OpenAPI и поднимает оболочку сервиса на демонстрационных данных. DS‑2 подготавливает базовую сетку, очищает пробелы и исследует внешние факторы. DS‑1 строит первый воспроизводимый baseline и валидирует WAPE.
5. Каждый работает в своей ветке и открывает PR. После одобрения PR обновляет `PROJECT_STATE.md` одной короткой записью. Координатор проверяет общий файл дважды в день и перед сабмитом.

## Репозиторий

```text
README.md             вход и запуск
AGENTS.md             правила для людей и ИИ-агентов
PROJECT_STATE.md      единый обновляемый журнал и решения
docs/PLAN.md          требования, роли, календарь, интерфейс, облако
docs/DATA_SOURCES.md  реестр источников и опытов
.gitignore            защита данных и секретов
```

Пути для будущего кода (`apps/api`, `apps/web`, `ml/`, `tests/`, `infra/`) согласовать с текущей структурой репозитория. Это стартовый **план**, сервис и модель ещё не реализованы.

## Важные ограничения

- Крайний срок, указанный в PDF: **27 сентября, 23:59 МСК**. Площадка хакатона остаётся источником актуального времени и формы сдачи.
- CSV имеет **ровно** строки, времена и поля образца сабмита; пятый маршрут присутствует даже при нулевом прогнозе.
- Результаты нагрузочного теста в README вносить только после реального замера с командой, железом, p50/p95, RPS, CPU и RAM.
