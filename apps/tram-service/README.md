# Веб-сервис прогноза посадок трамваев

Демонстрационный диспетчерский интерфейс для конкурсного прогноза на ноябрь–декабрь 2025 года. Показывает число успешных валидаций по маршруту и часу, обзор месяца по дням, схему доступных маршрутов, сценарную поправку и CSV-экспорт. Исходный файл `data/forecast.csv` — предоставленный командой `submission_tram_2025_nov_dec.csv`, для которого команда сообщила оценку 0.87571. Сервис не вычисляет эту оценку и не обучает модель.

## Запуск

Требуется Docker Compose. Пароль создаётся отдельно и не попадает в образ или Git:

Перед запуском из кода репозитория добавьте локально `data/forecast.csv` (конкурсный файл с сеткой 10 × 61 × 24) и при наличии — `data/routes.json`/`data/quality.json` из вашего закрытого пакета. Эти производные данные не коммитятся в репозиторий. Пакет `tram-service.zip`, переданный владельцу отдельно, уже содержит эти файлы.

```bash
python3 scripts/create_auth.py
docker compose up --build -d
```

Откройте `http://localhost:8080`. По умолчанию порт слушает только `127.0.0.1`. Для локального запуска без Docker: `python3 -m app.server` из корня проекта (Python 3.12+, файл `secrets/auth.json` уже должен быть создан). `GET /health` показывает готовность процесса.

При запуске контейнер переносит файл учётных данных с правами `600` во временную файловую систему, ограничивает доступ к копии и затем запускает сервер от пользователя `tram`. Это позволяет сохранить закрытые права файла на хосте. Если страница не открывается, выполните `docker compose ps` и `docker compose logs --tail=50 tram`; проверка порта: `http://127.0.0.1:8080/health`. После изменения Dockerfile пересоберите образ через `docker compose up --build -d`.

Для публичного сервиса установите TLS на reverse proxy и `COOKIE_SECURE=true`, задайте сильный пароль, ограничьте доступ к `/health`, используйте отдельное безопасное хранение секрета. Сервис читает файл при запуске, так что для смены прогноза или ключа сеанса нужен перезапуск. `secrets/auth.json` нельзя публиковать.

## API

Авторизация: `POST /api/login` с JSON `{"username":"...","password":"..."}`. Ответ устанавливает HttpOnly SameSite cookie на 12 часов. Остальные `/api/*` (кроме `/api/me`) требуют сеанса.

| Метод и путь | Результат |
| --- | --- |
| `GET /health` | Состояние процесса. |
| `GET /api/me` | `authenticated: true/false`. |
| `GET /api/routes` | Маршруты и признак наличия геометрии. |
| `GET /api/geometry` | Справочные остановки и трассы; значения посадок к ним не привязаны. |
| `GET /api/forecast?route=1&date=2025-11-01&period=day&factor=1` | По часам для дня; `route=all` для всех маршрутов, `period=month` для суммы по дням выбранного месяца. |
| `GET /api/export` | Те же параметры, CSV с разделителем `;`, UTF-8 с BOM. |

Параметр `factor` в диапазоне 0.5–1.5 умножает прогноз для сценария, по умолчанию 1. Ответ включает период, часовой пояс `Europe/Moscow`, единицы, источник и детальность. Границы дат: 2025-11-01…2025-12-31. Ошибки возвращаются как `{"error":{"code":"...","message":"..."}}` с HTTP 4xx. `period=month` суммирует исходные почасовые значения до применения коэффициента, затем округляет дневную сумму. При коэффициенте 1 сумма суток равна сумме часов. Сценарные округления могут дать небольшое отличие между почасовой и дневной суммой.

## Данные и география

- Цель: успешные валидации, то есть посадки, по маршруту и часу. Конкурсный файл содержит 10 маршрутов × 61 день × 24 часа = 14 640 строк; при старте проверяется полная сетка и допустимые значения. Маршрут 5 присутствует в файле, но отсутствует в исторической разметке; интерфейс предупреждает об этом.
- Геометрия получена из вкладки `Порядок_с_координатами` предоставленного справочника скриптом `scripts/build_routes.py`. Она есть только у пересечения маршрутов `{1, 5, 7, 11, 12}` с конкурсным набором. Строки справочника описывают варианты рейсов и остановки, а не посадки на этих остановках. Карта — схематическое отображение координат, без подложки улиц и без показателей на остановках.
- Вложения с исторической разметкой не нужны для обслуживания фиксированного прогноза и не входят в образ. Артефакт обучения и инференса команды пока не предоставлен; произвольные будущие даты сервис не прогнозирует.
- Чтобы заменить прогноз, положите файл с точной схемой `route;date;hour;prediction` в `data/forecast.csv` и пересоберите образ. Включена проверка 14 640 уникальных ключей и неотрицательных конечных значений. Для другого периода код временного диапазона и UI нужно расширить.

## Архитектура

`конкурсный CSV → проверка и загрузка в память → HTTP API → адаптивный интерфейс, график, карта и экспорт`. Один контейнер на стандартной библиотеке Python; зависимости frontend отсутствуют. Геосправочник преобразуется в JSON до сборки образа; пакет `openpyxl` нужен только для повторной генерации геометрии из XLSX. Авторизация: отдельный файл с PBKDF2-хешем пароля, HMAC-подписанный сеанс. Поскольку состояние прогноза неизменно, чтение можно горизонтально масштабировать, если все экземпляры получают один и тот же секрет сеанса и одинаковый образ данных.

Рекомендованный заданием Java/Spring и React — рекомендация, а не обязательное ограничение. Здесь выбран компактный стек для воспроизводимого запуска к дедлайну; API контракт позволяет заменить backend без переделки данных.

## Проверка и производительность

```bash
python3 -m unittest discover -s tests -v
```

Нагрузку измеряйте после запуска на указанном в задании контейнере 2–4 vCPU / 2–4 ГБ: отдельно `GET /api/forecast` для одного маршрута и всех маршрутов, `period=day/month`, с прогретым процессом и реальным сеансом. Зафиксируйте длительность, конкурентность, RPS, p50/p95/p99, ошибки, CPU и пик RSS; тестирующая машина должна быть отдельной. Цель задания — сотни RPS и p95 <200–300 мс, но это **не подтверждённый результат** текущего сервиса. Числа следует добавить сюда только после воспроизводимого замера на выбранной конфигурации Yandex Cloud.

## Ограничения и развитие

Нет потоковых фактов в реальном времени, прогноза новых дат и остановочной оценки. Справочник содержит геометрию только части маршрутов, маршрут 5 имеет плохую историческую основу. Сценарная поправка не переобучает модель и не говорит о причинном эффекте погоды или события. Для развития нужны артефакт модели, код признаков и инференса, внешние источники с доказанным эффектом, геопривязка фактических посадок, источник оперативных данных и проверка честности долгосрочного горизонта. Публичный запуск требует HTTPS, настроек секретов и замера производительности.

## Обновлённый интерфейс

После входа в шапке отображается статус авторизации; кнопка «Выйти» сбрасывает cookie через `POST /api/logout`. Нажатие маршрута в таблице или на карте открывает развёртку, а выбор дня, семи дней или месяца сохраняет маршрут. График и остановки кликабельны, карту и график можно переставлять перетаскиванием. На схеме показаны координаты из справочника; кнопка «Улицы» запрашивает тайлы OpenStreetMap непосредственно из браузера и при отсутствии Интернета возвращайтесь к схеме. Показатели по остановкам не рассчитываются.

`GET /api/forecast` поддерживает `period=week`: семь дней с выбранной даты, с усечением на 31 декабря. `GET /api/quality` отдаёт кандидатов на пробои и иллюстративную медиану аналогичных дней и часов. `scripts/build_quality.py` строит этот файл по предоставленной разметке. Диагностическое окно 06:00–22:59 не является подтверждённым расписанием; отсутствие записи, особенно на маршруте 50 в выходные, не доказывает сбой. Аналоги не подставляются в конкурсный прогноз.

Знак Московского транспорта в шапке загружается с Wikimedia Commons: источник Mos.ru, CC BY 4.0. Если браузер не может загрузить внешний файл, выводится текстовый запасной знак «МТ». Этот прототип не является официальным сервисом Дептранса.

Чтобы открыть сервис с другого устройства в доверенной локальной сети, замените `127.0.0.1:8080:8080` в `compose.yaml` на `8080:8080` и используйте `http://IP-компьютера:8080`. Публичный доступ требует HTTPS и `COOKIE_SECURE=true`.

## Сценарии, факты и карта: новые контракты

**Сценарный чат** работает без внешней LLM: `POST /api/scenario/preview` принимает JSON `{"text":"Маршрут 11, 03.11.2025, с 14 до 18, ремонт, −30%","date":"2025-11-01"}`. Он возвращает структуру и 24 пары `base/scenario`. Допустимы маршруты из конкурсной сетки, даты ноября–декабря 2025, интервал часов `[от,до)`, ручная поправка от −50% до +50%. Если процент не указан, сервер просит его уточнить; сам эффект погоды/ремонта он **не оценивает**. Применение меняет показанный график, а не исходный CSV. Экспорт остаётся базовым и явно так подписан. Относительные даты «завтра» для архивного периода отклоняются. API доступен только после входа.

`POST /api/scenario/interpret` принимает `{"text":"18 сентября дождь с 12-13","date":"2026-01-01"}` либо `{"text":"12-14 сентября дорожные работы на маршруте 11","date":"2026-01-01"}`. Ответ содержит нормализованный `intent` и статус `needs_location`, `needs_historical_backtest`, `needs_baseline` или `needs_event_model`, но **не предсказание**. `date` задаёт год по умолчанию при отсутствии года во фразе; веб-интерфейс использует текущий календарный год, показывает вывод и позволяет уточнить его текстом. Сентябрь 2026 не покрыт конкурсным CSV ноября–декабря 2025. Подробная спецификация для DS — `docs/DS_REQUIREMENTS.md`. Для численного прогноза нужен согласованный событийный пайплайн, обученная и валидированная модель, baseline на нужный год и контракт вывода; никаких скрытых коэффициентов для дождя и ремонта нет.

**Факт / прогноз** активируется при наличии `data/actual.csv` с заголовком из `data/actual.example.csv`: `route;date;hour;actual;status;available_at`. `status`: `complete`, `partial` или `corrected`; `available_at`: `2025-11-02T00:00:00+03:00`. Факт должен быть независимым проверенным источником за прогнозные даты. После добавления файла выполните `docker compose up --build -d`. `GET /api/actual?route=1&date=2025-11-01&period=day` возвращает совпавшие часы, значения и демонстрационные сигналы при модуле разницы ≥30% и ≥50 валидаций. Неполные часы исключены из сравнения и сигналов; отсутствующий час не равен нулю. Порог пока не калиброван DS и не является подтверждённой аномалией. Без файла экран показывает, что факты не подключены.

**Причины пробоев** показываются только если есть подтверждённый внешний источник в `data/events.json` (пример пустого файла — `data/events.example.json`). Элемент массива: `{"route":50,"date":"2025-09-14","start_hour":6,"end_hour":22,"title":"название подтверждённого события","source":"URL или документ","verification_status":"verified"}`. Если такого события нет, причина обозначается «не установлена». Сам диагностический список в `quality.json` не является доказательством сбоя.

**Геометрия оставшихся пяти маршрутов:** команда DS‑2 должна предоставить проверенный GeoJSON FeatureCollection с одной `LineString` на каждый маршрут 17, 25, 26, 28, 50, свойствами `route_id` и `source` (источник и права в отдельной документации). Из корня сервиса запустите `python3 scripts/import_geometry.py verified_routes.geojson data/geometry_extra.json`, затем пересоберите контейнер. Эти линии отображаются на карте без придуманных остановок и остановочного прогноза. При отсутствии файла интерфейс прямо показывает, каких линий не хватает.

Порядок панелей карты и графика сохраняется в `localStorage` этого браузера. Кнопка «Сбросить расположение панелей» возвращает исходный порядок. Это локальное предпочтение устройства, не настройка аккаунта.
